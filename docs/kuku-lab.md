# 九九ラボ　全体の思想とシステム（引き継ぎ用）

2026-11-20 時点（版 11/20d）。別のチャット・別の開発者が続きを進めるための資料。

---

## 1. 思想：となえない九九

- **九九は「唱える」のではなく「見て、わかる」。**
  点の絵（たて×よこ）を見て、5や10のかたまりで数をつかみ、答えが**ぱっと見**で出る状態をめざす。
- **かたまりで見る。**
  - 5のかたまり、5と5をくっつけた10のかたまり、正方形（3×3＝9、4×4＝16）を手がかりにする。
  - 9のだんは「10のまとまり − とうめい」（7×9 → 70 − 7）で見る。
- **ぱっと見（みどり）と、かたまりで確かめた（きいろ）を分けて扱う。**
  かたまりを使って確かめるのは悪いことではない（「それが だいじ」）。ただし、ステージのクリアにはぱっと見が必要。
- **まちがいは、かたまりで作り直して身につける。**
  まちがえた式は、点をおして自分でかたまりを作り、答え直す。
- **子どもが外の世界（ショート動画など）へ迷いこまない。**
  ホーム画面アプリ化と、おうちの方の確認で外へのリンクを守る（9章）。
- 表記は子ども向けに、ひらがなと分かち書き。おとな向けの画面は漢字かな交じり。

## 4. ステージ（30）と島（7）

`STAGES` の定義：`S(島, 名前, 式の一覧, まとめ?)`

| 島 | ステージ |
|---|---|
| A 5のしま | 5が1〜3本／5が4〜6本／5が7〜9本／5のだん まとめ |
| B ちいさな絵のしま | 2×2 2×3 3×2／2×4 4×2 3×3／2×5〜2×7／2×8 2×9 |
| C 3のしま | 3×4 4×3 4×4／3×5〜3×7／3×8 3×9／2・3のだん まとめ |
| D 4のしま | 4×5 4×6／4×7〜4×9／2〜5のだん ぜんぶ（まとめ） |
| E 入れかえのしま | ○×2 入れかえ／○×3 入れかえ／○×4 ○×5 |
| F 大きいだんのしま | 6×6 6×7／6×8 6×9／7×6 7×7／7×8 7×9／8×6 8×7／8×8 8×9／9×6〜9×9／6〜9のだん まとめ |
| G しあげのしま | にてる組／九九 ぜんぶ（まとめ）／10と11のだん／12のだん |

- 式 `[a,b]` は、たて a 行 × よこ b 列の点の絵になる。たてが「いくつずつ」、よこが「いくつ分」。
- **まとめのステージ**（review）は、各式1回のぱっと見でクリア。ふつうのステージは各式2回。

## 5. 1問の流れ（ふつうの問題）

1. 「スタート」（0.7秒）のあと、点の絵が出る。
2. 子どもは、たて・よこ・こたえ を入れる。
   - **タッチミスよけ：** 正しい答えにない数字は、一瞬赤くゆれて入らない。そのたびに時間を0.1秒たす（`rejects` に数える）。
   - 3つの欄がうまったら、すぐ判定する（けっていボタンは押さなくてよい）。
3. 必要なら点をおして、かたまりを作って確かめてよい（下の6章）。
4. 判定
   - **ぱっと見（pass）** ＝ 制限時間内（`P.limit` 秒。はじめは6秒。0.1秒の加算を含む）で、かたまりを使っていない。
   - pass なら大きな**みどりの丸**、そうでなければ**きいろの丸**と「3 × 8 = 24」を約0.9秒出して、自動で次へ進む（つぎへボタンはない）。
5. 記録
   - pass なら、その式のステージの合格回数（`P.sp['ステージ:a x b']`）を+1。pass でなければ0に戻す。
   - 復習で出た式は、pass なら苦手（`P.weak`）から外し、だめなら苦手に入れる。
   - `P.hist` に、時間・使った操作・rejects などを残す（最新300件）。

**出題（`pick()`）**
- 30%：前のステージの式を復習として出す（苦手は4倍出やすい）。
- 70%：いまのステージの式。まだ合格していない式が4倍出やすい。同じ式は続けて出さない。

**10問で1セット。** 全部ぱっと見で金、7以上で銀、それより少ないと銅のメダル。

## 6. 点の絵とかたまり（いちばん大事なところ）

- **点の並べ方：** 点線の仕切りで5×5のブロックに分ける。ブロックの中のまっすぐな5こが「5のかたまり」（unit）。
  - ブロックのたてが5のときは、たての5。よこが5のときは、よこの5。
  - **〜×5（よこが5）は、いつも横の5。** 上下でつなげて10（7×5 → 10・10・10・5）。
- **おす操作**
  - 5のかたまりの点をおす → 5になる。となりに5があれば、自動でくっついて10。
  - かたまりをおす → はずれる。10は5と5にもどる。
- **右下のすみ（たても よこも 5に たりない ところ）は、1回おすとまとめてかたまりになる。**
  - 正方形ならそのまま：3×8 → 10・5・9、4×9 → 10・10・16。
  - 正方形＋1列のときは、正方形を外がわ、1列を5のとなりに置く。
  - 細いところ（はばが2以下）で5より多いときは、「5と のこり」に分ける：2×4 → 5と3、7×8 のすみ6 → 5と1。
  - すみの5は、ほかの5とはくっつかない。
- **9のある式：** とうめいな玉（点線の丸）をたして、10のまとまりで見せる。
  - 9×n（たてが9）：下に1行たす。たての1列＝9こ＋とうめい1こ＝10。
  - n×9（よこが9）：右に1列たす（9×9は 9×n あつかい）。
  - 下に「10 が 7こ − とうめい 7こ」と出る。
- 絵の下の読み上げ行（`#read`）に「10 が 2こ　5 が 1こ　9」のように出る。

## 7. かたまりづくり（ステージ終わりの復習・レベルアップチャレンジ）

**共通**
- ぜんぶの点（とうめいな玉はのぞく）をかたまりにして、となりどうしの5と5を10にしてから、答えを入れる。
- できていないと判定しない。理由は絵の下（`#bhint`）に赤で出す。
- 時間制限はない。ぱっと見の記録（`sp`）には数えない。

**ステージ終わりの復習（MODE = fix）**
- 10問のセットで、ちがう数字を入れようとした式（`rejects` が1以上）があれば、「かたまりで たしかめよう」を出す。
- その式を1回ずつかたまりで作ってから、結果（メダル）画面へ進む。

**レベルアップチャレンジ（MODE = lvup）**
- 「つぎの ステージへ」を押すと、つぎのステージで初めて出る式（`newFactsOf`）から2つを選ぶ。
- それぞれ**3回続けて**かたまりで正解すると、レベルアップしてステージが進む。
- ちがう数字を押すと、その式の連続は0に戻る。
- あと1回のときは「⚡リーチ！⚡」の演出、達成したら「🎉レベルアップ！」の演出を出す。
- まとめのステージ（新しい式がない）は、チャレンジなしで進む。

**途中でやめたとき**
- 途中の状態は `P.fix`・`P.fixTotal`・`P.lvup = {to, facts, st}` に保存し、ひらき直しても続きから。
- ちず・おとな でステージを選び直すと、取り消す。

## 8. ごほうび・記録

- **メダル**（金・銀・銅）：10問ごと。メダルの棚に数がたまる。
- **ステージクリア、島のメダル、ライセンス**（全部の島）。ライセンスは印刷できる。
- **ダーツ（`darts.js`、九九・よむよむ共通の財布）**
  - ログイン：1日1本（アプリごと）
  - 銅：毎日1度、1本
  - 銀：そのステージで1度、+1本と銀ルーレット（1本×8・2本×3・5本×1）
  - 金：そのステージで1度、金ルーレット（銀の2倍）
  - 先生画面で支払い（はじめは全部の本数）、財布を1つにまとめる。
  - 財布は Firestore の `darts/{wid}`。子どもの記録の `wid` でつなぐ。
- **がんばりグラフ・つまずき：** よむよむと同じ形。`P.gh`（日付ごとの到達位置）、`P.days`（日ごとの問題数）、つまずきの多い式。
- **ぱっと見で見えた式**：`P.seen`（81マス中いくつ）。

## 9. 子どもを外に出さない（ホーム画面アプリ）

- **ホーム画面アプリ（PWA）**
  - `manifest.webmanifest` に `start_url` を書かない。ホーム画面に追加したときのURL（`?i=その子のコード`）で毎回開く。
  - 全画面で開き、アドレスバーがない。
- **おうちの方の確認**（`PWA.gate`、2けたのたし算）
  - 「おとな」を開くとき、「しょうたい」のとき（LINE・ブログへ出られる場所）に出す。
  - 子どもの画面には外へのリンクを置かない。
- **端末の設定の案内は「おとな」の中にある。**
  - アクセスガイド（iPhone・iPad）、アプリ固定（Android）
  - スクリーンタイムの「許可されたWebサイトのみ」、ファミリーリンク
- `sw.js` はキャッシュしない。前に「古いプログラムが残って二重登録」の事故があったため。

## 10. オンライン（Firebase）としくみ

- **Firebase プロジェクト：** `kuku-lab`。Firestore と Auth（compat 10.14.1）を使う。
- **先生のメール：** `terauchi@em-plus.net`（先生画面にログインできるのはこのメールだけ）。
- **URL がその子のかぎ（1コード1人）**
  - `?i=コード` を開く → `invites/{コード}` の `uid` の子の記録で始まる（どの端末でも同じ）。
  - まだだれも持っていないコードなら、ニックネームを決めて登録する。そのとき**先にコードをおさえる**（`uid`・`usedAt` を書く）ので、2人目は登録できない。
  - 以前の作りで同じコードに2人いる場合は、`cands` から選ぶ。
  - 端末には記録を持たない（Firebase が使えないときだけ `localStorage` の `kukulab-v6`）。

| コレクション | 内容 |
|---|---|
| `users/{token}` | `nick, code, inv, root, progress(P), stage, seen, cleared, wid, updated` |
| `invites/{code}` | 先生が発行（`by:'teacher', label, root`）／子どもが持つ（`by:'user', parent, root, nick`）／`uid`・`cands` |
| `board/{code}` | みんなの様子用（`nick, root, stage, cl, seen`）。かぎは入れない |
| `darts/{wid}` | ダーツの財布（`balance, earned, paid, claims, log`） |

- **しょうたい：** 押すたびに新しいコードを1つ作る。招待の枝（`root`）で、みんなの様子や先生画面をまとめる。
- **保存：** `save()` → `localStorage` と `cloudSave()`（1.5秒まとめて users を更新）＋ `boardSave()`。
- **ルール：** 九九の部分は「いまのルールと同じ。かえない」方針。ダーツ・よむよむ（`rst_*`）を足したものが `yomuyomu/docs/firestore.rules`。

**記録 P（`fresh()`）の中身**
`limit, stage, cleared[], sp{ステージ:式→合格回数}, weak{}, hist[], badges{g,s,b}, seen{}, days{}, gh{}, name, fix?, fixTotal?, lvup?`

## 11. 開発・確認のしかた

- **本番の Firebase には、テストでさわらない。**
- 確認は Playwright（Chromium）で、`file://.../index.html` を開いて行う。
  - `www.gstatic.com`（Firebase）と `fonts.googleapis.com` を空で返すと、端末だけのモードで動く。
  - 記録は `localStorage['kukulab-v6']` に入れて、`stage`・`lvup` などを作って始める。
  - オンラインの流れは、Firebase のにせもの（`el_convert_html/rst-kids/tests/firebase-mock.js`）を `addInitScript` で入れて確かめる。
- 点の絵は `#grid .cell`（かたまりのクラス：`c10`・`c5`・`csq`、とうめい：`ghost`）、入力はテンキー `.key`。
- 直したあとは `const VER` を上げてから push する。反映は数分。

## 12. これまでに決めたこと（変えるときは確認する）

1. 「まちがえた式」は、ちがう数字を入れようとした式（`rejects > 0`）。タッチミスよけで、まちがった答えはもう入れられないため。
2. レベルアップチャレンジは、新しい式を2つ、各3回連続。ちがう数字を押したら、その式は0から。
3. かたまりづくりは、ぱっと見の記録（ステージの合格）には数えない。
4. 5×5 も横の5になる（〜×5は横）。
5. とうめいな玉は、ふだんのぱっと見の問題の絵にも出す。
6. 「おとな」は、開くときだけ確認を出す（閉じるときは出さない）。
